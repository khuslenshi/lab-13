# Self-Evaluation — F.CSM311 Бие даалт 13

## 1. Хэрэв шалгалт өнөөдөр болбол би энэ кодыг өөрөө бичиж чадах уу?

**Хэсэгчлэн — тайлбартай**

FastAPI-ийн үндсэн бүтэц, endpoint тодорхойлох, Pydantic model үүсгэх зэргийг өөрөө бичиж чадна. Учир нь AI үүсгэсэн код бүрийг уншиж ойлгосон.

Гэхдээ Motor async driver-ийн нарийн API (`.to_list(length=...)`, `find_one_and_update` параметрүүд) болон MongoDB query operator-уудыг documentation харалгүй бичихэд хэцүү байх. Эдгээрийг AI-тай хамтран хийсэн ч гүнзгий цээжилсэн гэж хэлэхэд хэцүү.

Unit test-ийн mock strategy — `unittest.mock.AsyncMock`, `patch` ашиглах аргыг ойлгосон ч гараас бичихэд documentation хэрэгтэй болно.

## 2. Дахин хийнэ гэвэл юуг өөрөөр хийх вэ?

**AI session-г эрт, олон удаа хадгалах.** Энэ удаад зарим чухал session-г дараа нь хадгалахыг оролдоход context алга болсон байсан. Дараагийн удаад session бүрийг дуусаагүй байхад нь тэмдэглэх болно.

**Өөрөө эхлээд бичиж, дараа AI-г ашиглах.** Зарим функцийг шууд AI-д бичүүлсэн. Эхлээд өөрийн хувилбарыг бичиж, дараа нь AI-тай харьцуулсан бол ойлголт гүнзгийрэх байсан.

**Commit-уудыг жижиг, тодорхой хийх.** Зарим commit хэт их өөрчлөлт агуулсан. Feature бүрийг тусдаа commit болгон хийвэл history нь уншихад хялбар байх байсан.

**CLAUDE.md-г эхний өдрөөс бүрэн бичих.** Бие даалтын эхэнд CLAUDE.md хагас дутуу байсан учраас AI заримдаа зөрчилтэй санал болгосон. Эхнээс нарийн тодорхойлсон бол илүү тогтвортой үр дүн гарах байсан.

## 3. Энэ туршлагаас юу сурсан бэ?

**AI бол хурдасгагч, орлуулагч биш.** Энэ бие даалтын хамгийн том сургамж энэ байсан. AI код бичиж чадна, гэхдээ тэр код зөв эсэхийг шалгах, ойлгох, систем болгон нэгтгэх ажил хүний дээр үлддэг.

**Hallucination бодит асуудал.** AI алдаа гаргадаг, тэр алдаанууд заримдаа итгэмээргүй байдлаар нарийн харагддаг. "Verify, don't trust" зарчим практикт үнэхээр чухал гэдгийг мэдрсэн.

**Prompt чанар үр дүнг шууд тодорхойлдог.** Тодорхой, нарийн prompt өгөхөд AI илүү ашигтай хариулт өгдгийг ажиглалаа. "FastAPI CRUD endpoint бич" гэхээс "FastAPI-д MongoDB Motor ашиглан async PATCH endpoint бич, partial update хийх, 404 error handle хий" гэж асуухад илүү сайн код гарсан.

**AI workflow нь програмчлалын мэдлэгийг устгадаггүй, харин шаардлагыг өөрчилдөг.** Код бичих мэдлэгийг бага шаарддаг болж, харин системийн дизайн, верификаци, debug хийх чадварыг илүү шаарддаг болж байна. Энэ шилжилтэд бэлтгэх хэрэгтэй гэдгийг ойлгосон.
